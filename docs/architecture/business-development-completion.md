# 业务分发代码完成标准

2026-11-03 按用户最新要求，先完成代码，随后安排多系统测试。BM0–BM10 的历史实测结果保留；本阶段不把未执行的原生场景标为通过，也不执行正式发布。

任务树与可测试目标：

1. skills 和执行入口
   - 核对 31 个公开 skill 的独立入口、资源闭包、相对路径和脚本语法。
   - 完成 Windows 单 skill、业务集合、系统集合的首次原生安装预览。
   - Windows 受管软链接模式在写入前明确拒绝；复制、版本冲突、共享归属和迁移保持完整。
   - 验收：package、install、ownership、migration 的本地行为检查通过；两个业务离线集合无需先有 Bash 即可原生 Plan。
2. 分发与发布工具
   - 31 个独立归档、2 个业务集合、10 个系统集合，各提供 ZIP/tar.gz，共 86 个归档。
   - 精确成员锁、来源提交/工作区状态、资源摘要、包摘要、归档摘要与统一索引。
   - 离线集合支持迁移目录后的安装、升级、卸载；独立归档保持 skill 字节一致，可直接复制。
   - 验收：重复构建全部字节一致；12 个集合全部完成本地离线生命周期；篡改、缺失和错误来源被拒绝。
3. CI、发布验收及使用文档
   - PR/push 覆盖生成、独立执行、归属、迁移、离线打包和重复构建。
   - 正式候选要求干净提交，BM0 冻结的 BM0–BM9 必需项和 30 个原生正向项均有匹配候选摘要的成功证据。
   - 通过可信本地清单重新下载发布物并验证，失败不留下被误当作完成的下载目录。
   - 文档包含单个、业务、系统、远控、升级卸载路径，说明首次 Bash、jq、程序与技能安装的区别。
   - 验收：门禁能拒绝缺项、跳过、旧包、旧清单和错误回执；本地 HTTP fixture 下载复验通过。实际公网发布复验留在 BM10。

每组实现后本地自检，发现失败最多优化三轮。只有存在真实产品语义选择或三轮仍未达成时才暂停。远端网络故障不在本轮重新触发；程序依赖的未发布候选状态保持可见。

代码完成不等于多系统验证完成、release-ready 或已发布。这三种状态分别记录在 `docs/verification/business-distribution-status.json` 的 development、历史 milestones 和发布证据中。
