# KA8 定位追加轮：证据在哪一层变成了错误结论

目标不变：模型自主分析和组合工具，skills 执行明确操作，宿主管理目标、权限、保护和生命周期。本轮完成三次定位优化，没有向模型加入 Docker 诊断次序、固定答案或强制调用规则。

## 任务树与验收标准

1. 优化一：核查事实交付与模型配置敏感性。
   - 审计模型会话里的实际工具消息，不用本地采集日志替代模型看到的内容。
   - 校验来源、UTF-8 字节偏移和原文，区分未返回的窗口、搜索行前缀与完整文件。
   - 用相同原始 C02/C11、工具、DeepSeek 原生默认 high 和资源上限，核验已配置的 Pro 模型；对照既有 Flash high 结果。
   - 验收：错误结论能追溯至工具原文或模型自己的推断；不因模型名字假定质量。原 rubric、失败和预算保留。
2. 优化二：历史源码删减对照。
   - 只移除三个历史源码文件，保留当前 init、procd 记录、UCI、生成配置、登记及日志的全部原始字节。
   - Flash/Pro × C02/C11，共四个单次会话。删减输入另存，不替换原验收场景。
   - 验收：核查没有历史源码时，是否仍出现迁移阶段、摘要含义或当前守卫调用链的无依据结论。
3. 优化三：名称不变性对照。
   - 只把数据路径换成不暗示状态的名称，把重复字符摘要换成不同的、格式正确的摘要伪名。
   - 保留路径中的空格、冲突/相等关系、active、不同摘要字段、全部代码与直接错误证据。
   - 相同 Flash high、C02/C11，共两个单次会话。
   - 验收：模型不能仅因名称变化就获得另一套事实；有帮助的变体也不能抹去原场景失败。

三个实验均维持温度 0.2、4096 输出 token、24 次调用、64 KiB 请求体和 180 秒上下文期限。原生 DeepSeek 适配器对空 effort 使用 high；记录中本地 effort 为空仍保留，不把上游实际推理深度当成已证明。超时结果耗时包含 Agent 收尾，实测 186.5 秒，不能冒充期限内完成。

## 已定位的问题

### 关键文本已交付，错误出现在解释阶段

新增交付审计对照前轮 32 个模型会话。将文字读取与 literal search 的实际返回前缀一并计入后，32 个都收到了本轮逐项选择的关键文本：当前启动命令、日志、登记的 active 和目标路径，或 C12 的退出状态及 completed 回执。所有已返回窗口与相应来源的字节匹配，未发现文本改写或偏移错误。

这只证明所抽查文本被交付，不证明所有文件都读完、所有事实都正确，也不证明模型理解了它们。全部七个前轮核心失败会话都已拿到对应反证。不能再用“技能没有采到这几项数据”解释这些失败。

确定性负对照验证：在 direct-dockerd 的 C11 模型消息中查找“procd 实际启动 quickstart-storage-guard”，审计返回未交付；用户、系统、模型自己的话和本地 observation 副本不能被冒充成来源事实。搜索命中被截断时，其未返回的后半行也不能算已读。

### 模型把名称与差异补成了运行状态

原始 C02 中，路径含 `retired`、`handoff`，两个不同字段的脱敏摘要分别为重复的 a 和 b。模型把这些线索补成了“卷已退役”“handoff 未完成”“目录不合法”“迁移未收尾”，尽管没有目录检查、状态字段定义或摘要输入范围。

更换 Pro 没有解决该问题。它在原 C02 中依旧用摘要差异暗示迁移未完成，并补出未提供的 `GuardReady → GuardCheck` 调用关系。原 C11 则超时，没有最终回答，不能评分为通过。

移除历史源码也没有根治。两个模型都继续在 C02 中推断半迁移状态。Pro 在 C11 中进一步断言：active 表示未完成、正常终态应为 completed、守卫因摘要不符把目录挂成只读。删减输入没有守卫源码、挂载表或挂载操作记录，工具也未返回这些结论。这是明确的模型外推，不是 skills 实施了挂载或给出了诊断。

### 名称替换能改善一例，但没有消除虚构调用链

中性名称下的 Flash C02 通过原核心 rubric：保留路径冲突，正确说明 active 接受范围、GuardReady 缺失、源码对应关系及摘要范围未知，不再把空格直接判为非法目录或把名称判为半迁移。

但同组 C11 仍凭历史源码断言“守卫是外层启动路径上的包装”，又把日志解释成已经越过前置检查。实际 init/procd 记录直接启动 dockerd；材料没有证明该外层守卫被执行。名称变化未解决这一类当前调用链外推。

这是每格一次的定位实验，不能把波动全归因于名称，也不能据此声称总体质量提高。原始场景仍须通过。

### 自述采证范围也会超出实际调用

删减源码的 Flash C11 主体判断正确，却说两个 init 都已逐窗口读完。工具记录中固件 init 的 4096–8191 字节没有读取。新增审计能把“确实交付了关键片段”和“整份文件已检查”分开，避免报告再次放大模型的自述。

## 工程改动与验证

- kai-skills 新增开发侧 `audit_delivery.py` 和五项测试。它检查已交付文本，不执行目标脚本、不判业务根因、不改变运行时提示。
- Reasonix 提交 `39005d2bc` 新增 QA 专用的显式中断记账入口。普通运行仍拒绝未结算账本；操作者只可对已有终止结果、原 4096 输出和单次 provider 请求记录，永久保留其完整费用上界。重读账户计数、重复执行入口均不能释放该上界或重放失败会话；重试聚合及未知请求次数继续阻断。
- 新入口的先失败后通过测试验证了保留费用不会在账户对账时消失。这是新增显式恢复能力的验证；原实现自动阻断未结算请求本来就是正确行为，不把它说成旧版会自动漏算。
- Go capability-eval 包通过。Python 的五项交付审计、四项评测材料检查及三项 Docker 采证检查通过。canonical 能力、生产 Agent 路由、系统提示和内嵌快照本轮未修改，不冒充完成了新一轮原生平台或生成发布验收。

原 CNY20 累计上限和最初基线不变；超时请求的完整上界 CNY1.55648 永久保留。共享账户计数还可能包含其他并发使用，不能作为本实验独立账单。最终账本、全部结果与清理记录见结构化证据。

## 阶段决定

三次定位优化结束，KA8 仍 failed，KA9/KA10 未开始。没有运行完整 216 会话或原生平台矩阵，没有发布或部署本批改动，KaiPlus 最终内嵌同步仍属于 KA10。

当前证据把这些失败定位到了模型对证据的外推与自述范围，而不是已抽查的关键文本丢失。能力实现正确、模型事实忠实性与最终任务成功须分别记录；本轮不擅自取消模型关键事实门槛。通过添加固定 Docker 诊断流程、隐藏反证、强制模型选工具或只保留成功变体来过关，都不符合原目标。
