# KA8 第三次追加轮次：修正计量与三组对照

## 任务树与验收标准

1. 优化一：修正准入计量，冻结完整三组对照。
   - 回归先复现：实际 HTTP body 为 199 字节，旧通用投影却计为 160112 字节。
   - 可选 RequestSizer 使用 OpenAI 客户端正式 buildRequest 与 JSON encoder；请求感知的准入接口拿到 Agent 当次实际请求，保持原 provider 和鉴权错误处理。
   - 计入工具定义、额外字段、配对修复、JSON 转义与换行；排除 Qwen 不回传的推理和本地诊断；保留 DeepSeek 回传的推理。
   - 64 KiB 上限、4096 输出、24 次调用、180 秒及原 CNY20 累计预算均不扩大。未知适配器或序列化失败在预约费用和发请求之前停止。
   - 验收：真实序列化回归和相关包通过；4 卡 × 3 条件 × 2 配置 × 1 次，共 24 个会话全部保留，按原 rubric 判分。
2. 优化二：以相同材料和资源上限核验 deepseek-v4.1-flash、deepseek-v4-flash 的原生高推理配置。
   - 不再额外声明自定义 supported_efforts。客户端 DeepSeek 适配器对空 effort 的原生默认是 high；没有显式词表时，配置的 default_effort 本身不等于 EffectiveEffort，原始结果中空值保留。
   - C02/C11、两模型、提供能力条件，共 4 个定点场景。全部完整、核心与事实准确性均通过才扩展完整对照；否则保留失败。
3. 优化三：只切换同两模型的可选 thinking 为 disabled，其他输入、工具和资源限制不变。
   - 同样先跑 4 个关键场景；模式开关的上游内部实现不作不可观察的保证，记录返回的推理 token 和文本。
   - 若仍有关键错误，三次优化结束，不再更换模型或增加任务处方。
