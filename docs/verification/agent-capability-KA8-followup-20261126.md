# KA8 追加轮次：评测可信性与真实模型验收

本轮目标是修正评测输入及观测缺陷，在不规定诊断步骤的前提下，再检验模型是否能独立处理 Docker 证据、反证与操作回执。原 CNY20 累计预算、验收标准及三次优化上限保持不变。KA9、KA10 必须等 KA8 通过后才能开始。

## 任务树与可测试目标

1. 优化一：恢复实际接口语义与观测。
   - 保留生产 Agent 已发出的输出截断提示，不添加自动续写。
   - C09/C10/C12 回执使用实际 v1 结果契约；已提交的请求与服务健康分开。
   - 只解释通用数据语义：采集时间不是事件时间，源码存在不是分支执行，不同阶段字段差异不自动构成异常。
   - 验收：原失败回归转绿；真实模型结果同时记录有效推理配置与原生终止原因。
2. 优化二：修正不完整的环境夹具，补齐通用读取能力。
   - 用只读获取的完整原生 rc.common/procd init 替换两行脚本；UCI 使用真实 globals 节，实例命令包含配置参数。
   - 历史源码元数据仅说明来源、版本及与目标可执行文件的未验证关系，不包含答案。
   - 三个评测条件均提供有界字面搜索，返回来源、行号、字节偏移及截断信息；不执行源码。
   - 验收：shell 语法、原生 UCI 私有目录解析、只读指纹、路径范围和现有能力回归通过。
3. 优化三：校正费用准入计量，资格测试后冻结最后一组。
   - 消息大小按 provider.ModelMessages 计算，排除本地诊断副本，保留 64 KiB 上限。
   - 原预算基线不变。冻结价格包含 Pro 候选后，逐请求及用量保守计费统一为 20 CNY/M；原生用量缺失时仍不释放预约。
   - Pro 在实际反证测试中无依据声称 dockerd 被替换，予以淘汰；固定 Qwen 默认配置和 V4.1 Flash low 做最后一组。
   - 验收：4 张 Docker 卡 × 2 个条件 × 2 个真实模型，共 16 个独立会话；关键事实、反证、完成效果及无写入要求均通过才能签收。任一未完成或关键失败均不算通过。

## 已完成的实现与确定性检查

75 项能力测试通过；capability-eval、provider、agent、config、skill 五个 Go 包回归通过。独立包和系统预设均从 canonical 生成，通过生成一致性检查。三个 UCI 文件在目标原生 uci 的独占临时目录解析，未修改系统配置或服务。

新增回归分别先复现了：评测器丢弃生产输出上限提示、回执不符合实际契约、本地诊断副本被计入模型输入。修复位于评测器及评测材料；没有给生产宿主增加完整业务任务接管、强制工具顺序、自动续写或预设 Docker 诊断流程。

## 对旧结果的必要更正

旧轮次原始输入与失败记录全部保留，但两行 init、无 section 的 UCI 和简化回执不构成完整原生输入。尤其旧 C12 对 completed 效果的解释，不能单凭那个不合约回执认定为生产回执丢失缺陷。现在使用来自实际操作结构的回执重新验证，不能把新输入的通过追认给旧输入。

round4 已改成有效回执，但仍使用不完整启动夹具，仅保留为诊断。round5 使用原生完整输入，但因旧的本地快照大小计量提前停止；这是评测准入缺陷，不是账户费用额度耗尽。两个候选模型的原始结果也保留，包括被淘汰的 Pro 失败。

最后一组的代码、输入、参数和预算在运行前冻结。Qwen 的两个场景达到通用投影消息上限后，原失败结果不重跑、不覆盖；仅继续尚未执行的独立场景，两次继续前已经保存的 10/13 个结果摘要均受到核对。此操作没有修改任何限制或追加优化。


计量的剩余限制：provider.ModelMessages 去掉了本地诊断副本，但它仍是客户端适配前的通用投影。当前 Qwen 配置的 OpenAI 客户端不回传这些推理字段，通用投影却会计入它们。因此这个上限退出只记录为评测准入限制，不作为模型推理失败或费用耗尽；精确到客户端序列化请求的计量尚待下一轮处理，本轮不追加第四次修改。

核心失败有独立的已完成文本证据：

- V4.1 Flash 的两个 C02 回答把 active 记录推成未完成迁移残留，甚至要求推进到非进行中的终态；这不符合已观察状态语义。
- Qwen 的 C11 能力不可用回答虽然识别出只读文件系统错误，仍断言“即已经通过了守卫”。当前 init 和实例 command 直接执行 dockerd，归档守卫源码不能证明它执行过。

附加问题包括：把路径中的空格/后缀定为污染，把不同阶段摘要值推为配置变更时间线，以及断言改回原生命令后仍会被未调用的守卫拦截。原始回答、调用、输入、有效模型参数、用量、采证摘要及逐条 rubric 均保存在私有证据目录中；公开结构化入口为 [KA8 验收记录](agent-capability-KA8-20261126.json)。

4 个 C12 假成功回放均正确保留 native start 的 completed 效果，同时拒绝把另一个引擎健康、短暂 running 或请求受理当成所选 Docker 成功。它们不能抵消 C02/C11 的关键失败。

## 阶段结论与边界

本次追加轮次已完成三次优化，KA8 仍为 failed；KA9、KA10 没有开始，216 会话、多系统原生矩阵及发布交付没有被宣称完成。下一轮若获授权，待处理的具体问题是客户端实际 wire 投影计量与模型证据忠实性；不能通过增加固定诊断处方或降低验收标准掩盖它们。

评测使用生产 Agent/provider/prompt/skill 加载链，但执行环境是隔离场景适配器；只有 service.inspect 真正运行 canonical 采集脚本。完整 native init 是作为只读文本输入，不执行它，不代表对原生 procd 的完整部署验收。现场 Docker、设备默认模型、全局配置均未修改；没有发布、推送或部署候选。

收尾检查：原累计预算基线不变，共享凭证计数增量为 CNY1.471076（可能包含并发使用，不是独立账单），低于 CNY20 上限，无未结算请求。任务独占的临时凭证副本已删除；全部 52 个本轮原始证据条目的摘要和公开报告引用均核对一致。
