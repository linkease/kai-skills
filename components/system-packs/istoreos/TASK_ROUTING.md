# iStoreOS capability directory

Historical filename retained for compatibility. This is a discovery catalog, not task routing. The model may combine capabilities, use generic tools, or use no skill. No row imposes a prerequisite, primary skill or completion gate. Lack of a dedicated skill must not block analysis.

| Capability | Facts or explicit effects |
| --- | --- |
| `kai-dev-environment` | 查询、安装、验证和执行明确选择的 mise SDK 或 uv；保留精确版本、来源和原生错误。 |
| `kai-download-acceleration` | 检查文件、Git、Docker 和开发下载加速，并核对本次网关与校验证据。 |
| `kai-project-dependencies` | 在指定 SDK、管理器和项目中查询来源或执行依赖操作；保留锁格式和项目隔离。 |
| `kai-project-run` | Plan or execute an explicitly selected Node, Python or Go project transaction with exact SDK, source hashes, locks and expected output. |
| `kai-software` | 按来源限定身份查询软件候选、登记版本和文件归属；对明确选择的软件执行安装或移除事务。 |
| `kai-storage-files` | 在明确路径查询容量、空间占用和文件名；返回实际后端、范围、错误及持久性证据。 |
| `kai-system-information` | 返回实际目标的系统、包管理器、下载工具与容器运行时事实；按所选范围只读查询，保留未知项和证据来源。 |
| `kai-tool-bootstrap` | 查询或准备指定目标上的 Bash、完整 jq、mise 和内部客户端；返回实际路径与校验结果。 |
| `istoreos-app-diagnostics` | 读取已记录的 iStore 安装日志、包数据库和目录信息；返回有范围与来源的事实及启发式分类。 |
| `istoreos-app-search` | 查询 iStore 聚合目录，返回有来源标识的应用候选、精确名称和摘要。 |
| `istoreos-backup-restore` | 查询原生恢复能力，或对明确模板、恢复点和不可变预览发起单项 ChangeGuard 操作。 |
| `istoreos-docker-acceleration-istoreenhance` | 查询既有 iStoreEnhance/KSpeeder 服务证据；对明确服务请求执行经过验证的原生动作。 |
| `istoreos-docker-basics` | 只读查询 Docker 启动入口、各配置来源和运行时；分别呈现目录冲突与 API 可用性。 |
| `istoreos-docker-data-root-migrate` | 验证并复制明确的静止 Docker 数据集到空目标；保留挂载身份、元数据与实际复制结果。 |
| `istoreos-download-acceleration` | 兼容旧 ID 的明确接口；公共能力为 kai-download-acceleration，不执行任务分流。 |
| `istoreos-kspeeder-domainfold-fetch` | 使用已有本地 KSpeeder 接口映射或下载明确 URL；不安装或自动启动服务。 |
| `istoreos-logs-and-diagnostics` | 按显式范围读取 iStoreOS 服务、网络、存储或包登记事实；保留未知、拒绝与超时。 |
| `istoreos-luci-recovery` | 读取 LuCI 相关服务和文件归属；对明确服务或单个本地 opkg 包执行有界操作。 |
| `istoreos-mise-runtime` | 兼容旧 ID 的明确接口；公共能力为 kai-dev-environment，不执行任务分流。 |
| `istoreos-network-quality` | 兼容旧 ID 的明确接口；公共能力为 kai-network-quality，不执行任务分流。 |
| `istoreos-package-manager` | 兼容旧 ID 的明确接口；公共能力为 kai-software，不执行任务分流。 |
| `istoreos-quickstart-api` | Send one explicitly selected QuickStart API request through a bound LuCI transport; return its actual response envelope. |
| `istoreos-run-executable` | 分别检查本地文件、下载经过摘要校验的文件，或使用明确 runner 执行选定的本地程序副本。 |
| `istoreos-service-manager` | 读取 init、UCI、生成配置、procd、日志和文件归属；执行有明确前置状态与后置验证的单项服务操作。 |
| `istoreos-source-introspect` | 读取指定 iStoreOS 服务的启动源码、配置及原生文件归属；输出脱敏且可展开的证据。 |
| `istoreos-storage-path` | 兼容旧 ID 的明确接口；公共能力为 kai-storage-files，不执行任务分流。 |
| `istoreos-system-task-router` | 按调用者明确选择的范围查询 iStoreOS 设备事实；历史 ID 保留，不再进行任务分流。 |
| `istoreos-systools` | 查询明确的系统范围，或执行所选原生 systools 动作；返回原生退出结果。 |
| `kai-network-quality` | 用已有 FastNet 测量明确端点或网络 profile，返回有预算、来源和不健康事实的观察。 |
